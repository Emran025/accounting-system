# مصفوفة التتبع والاعتماد — منصة المنتجات والعروض

**العقد المرجعي:** `marketplace_contract@1.0`
**حالة الوثيقة:** مسودة مراجعة قبل البناء.

> هذه المصفوفة تمنع بدء واجهات أو جداول أو API قبل معرفة المتطلب الذي تخدمه، ومصدر بياناته، والطرف الذي يختبره ويعتمده.

| المعرّف | المتطلب القابل للتحقق | مصدر الحقيقة | مكوّن Accore المقترح | مكوّن المنصة المركزية المقترح | دليل القبول | مالك الاعتماد |
|---|---|---|---|---|---|---|
| MR-001 | لكل مؤسسة ملف تاجر عام فريد وحالة تحقق قابلة للسحب. | `MerchantProfile` في Accore | `Commercial/Marketplace/Models/MerchantProfile` | `public_merchants` | لا تظهر صفحة التاجر قبل `verified`؛ ويخفي التعليق كل المنتجات والعروض. | الحوكمة والتجارة |
| MR-002 | يبقى المنتج التشغيلي داخل كتالوج Inventory ولا تكرر قواعده في المنصة العامة. | `Product` في Accore | ربط `CatalogPublication` بـ `product_id` | `public_products` projection | نشر/تعديل/سحب من دون تعديل سجل المنتج الأصلي. | العمليات والمعمارية |
| MR-003 | لا تكشف الواجهة العامة تكلفة أو هامش أو مخزوناً دقيقاً. | قائمة السماح للعقد | `MarketplaceProductSnapshotFactory` | `PublicCatalogProjection` | اختبار عقد ينفي الحقول المحظورة في كل response عام. | الأمن والمالية |
| MR-004 | يستطيع التاجر نشر منتج متعدد اللغة بفئة وصورة غلاف وسعر ووحدة. | `CatalogPublication` | إجراءات اعتماد المنتج ووسائطه | فهرس/صفحة المنتج | رفض النشر عند غياب الاسم أو السعر أو أهلية البيع أو الغلاف المطلوب. | التجارة |
| MR-005 | يكون العرض كياناً مستقلاً موجهاً لمنتج/فئة/مجموعة وبنافذة زمنية. | `OfferCampaign`, `OfferTarget` | `Commercial/Marketplace` | `public_offers` | ينتهي العرض عند `ends_at` ولا يبقى على البطاقات أو نتائج البحث. | التجارة والقانوني |
| MR-006 | يدعم النظام صور الغلاف والمعرض والحملة مع نص بديل وبصمة وحالة جاهزية. | `PublicMediaAsset` | خدمة وسائط السوق | تخزين كائنات/معالجة/CDN | لا يظهر أصل قبل `ready`؛ والسحب يستبدله بأصل بديل. | المحتوى والأمن |
| MR-007 | تقبل المنصة تكرار الرسائل من دون ازدواج سجل أو عرض. | `event_id`, `idempotency_key` | transactional outbox | inbox/deduplication store | إرسال الحدث مرتين يعيد الإيصال نفسه ولا يضاعف النتيجة. | المنصة والهندسة |
| MR-008 | يرفض المستقبل revision أقدم من النسخة المقبولة. | `revision` لكل كيان | مزود revision | optimistic concurrency | إرسال revision 7 بعد قبول 8 يعيد `409 STALE_REVISION`. | الهندسة |
| MR-009 | يمكن استرداد التزامن بعد انقطاع الشبكة دون فقد نشر. | outbox + cursor + snapshot | عامل إرسال ومصالحة | cursor API | إيقاف الشبكة ثم استئنافها يعيد إرسال كل الأحداث بالترتيب المنطقي. | التشغيل |
| MR-010 | يمكن للزائر البحث والتصفية بين تجار مؤسسات مختلفة من دون اتصال مباشر بكل ERP. | projection مركزية | لا ينفذ بحثاً عاماً | index/search service | تظهر النتائج من الفهرس عند إيقاف خادم مؤسسة بعد آخر مزامنة سليمة. | المنتج والأداء |
| MR-011 | لا تقبل هوية الخدمة المؤقتة الخاصة بلوحة الإدارة كهوية تكامل إنتاجية. | مفاتيح/عملاء خدمة | client credentials + signing | signature verification | يرفض طلب بلا توقيع أو بنطاق تاجر مخالف أو timestamp قديم. | الأمن |
| MR-012 | تعرض لوحة Accore حالة كل نشر وسبب آخر خطأ وإيصال الاستلام. | `MarketplaceSyncReceipt` | شاشة Sync Audit | receipts | يستطيع مستخدم مخول تتبع `event_id` إلى `receipt_id` وسبب الفشل. | الدعم والتشغيل |

## مصفوفة البيانات الممنوعة من النقل العام

| الحقل أو الصنف | سبب المنع | البديل العام إن لزم |
|---|---|---|
| `weighted_average_cost`, `cost_price`, `purchase_price` | سرية تجارية ومالية. | لا بديل. |
| `minimum_profit_margin` | سياسة ربح داخلية. | لا بديل. |
| `stock_quantity`, `low_stock_threshold` | يكشف التشغيل ومخاطر التلاعب أو المنافسة. | `availability` وصفي فقط. |
| الموردون وطلبات الشراء | علاقات تعاقدية داخلية. | اسم التاجر البائع فقط عند النشر. |
| بيانات العميل والموظف | خصوصية وامتثال. | طلب اهتمام بحد أدنى وموافقة صريحة. |
| معرفات مستخدمي ERP وسجلات التدقيق التفصيلية | أمن وتتبّع داخلي. | `catalog_revision` ووقت آخر تحديث فقط. |

## مصفوفة الصلاحيات المقترحة

| الصلاحية | القدرة | لا تخول |
|---|---|---|
| `marketplace.merchant.manage` | تعديل ملف التاجر وإرساله للتحقق. | اعتماد التاجر أو تعديل تاجر آخر. |
| `marketplace.catalog.manage` | إعداد لقطة المنتج والصور وإرسالها للمراجعة. | تجاوز أهلية المنتج أو النشر المباشر. |
| `marketplace.catalog.approve` | اعتماد أو رفض نشر المنتج. | تعديل السعر التشغيلي أو المخزون. |
| `marketplace.offers.manage` | إعداد عروض المؤسسة وجدولتها. | اعتماد العرض إذا كانت السياسة تتطلب فصل الواجبات. |
| `marketplace.offers.approve` | اعتماد/سحب العرض. | تعديل إعدادات العقد أو مفاتيح الخدمة. |
| `marketplace.media.manage` | رفع وربط وسحب الوسائط العامة. | تجاوز فحص المحتوى أو مراجعة الحقوق. |
| `marketplace.integration.audit` | عرض الإيصالات والأخطاء وإعادة المحاولة المصرح بها. | قراءة محتوى تجار آخرين أو بيانات أسرار. |
| `marketplace.contract.admin` | تدوير بيانات اعتماد الخدمة وتغيير endpoint بعد موافقة مزدوجة. | تعديل تسعير أو منتجات. |

## اختبارات بوابة القبول

| البوابة | الاختبار الإيجابي | الاختبار السلبي الإلزامي |
|---|---|---|
| Contract | يقبل `marketplace_contract@1.0` الصحيح. | `406` عند نسخة مفقودة أو غير متوافقة. |
| Authenticity | يقبل طلباً موقّعاً بنطاق التاجر الصحيح. | `401` عند توقيع خاطئ أو timestamp منتهٍ أو replay. |
| Publication | ينشر منتجاً صالحاً وصورته `ready`. | `422` لمنتج غير sellable أو بلا سعر أو وسائط مرفوضة. |
| Offer | يظهر العرض في نافذته ويختفي بعدها. | لا يقبل نهاية قبل البداية أو هدفاً فارغاً. |
| Privacy | تعرض الصفحة العامة الاسم والسعر والوسيط والتوفر. | لا تجد مفاتيح التكلفة/الهامش/المخزون في JSON أو DOM. |
| Reliability | يعالج outbox انقطاعاً ثم مصالحة. | لا ينشئ التكرار صفاً أو بطاقة مكررة. |
| Withdrawal | يخفي تعليق التاجر كل الإسقاطات. | لا تبقى بطاقة مخبأة في نتائج البحث أو CDN بعد زمن السحب المعتمد. |
